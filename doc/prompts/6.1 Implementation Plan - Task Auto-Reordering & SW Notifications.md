# Implementation Plan - Task Auto-Reordering & SW Notifications

This plan details the implementation of automatic task reordering based on streaks, and background notifications using Cache Storage inside the Service Worker.

## User Review Required

### Open Questions
> [!IMPORTANT]
> **Streak Sorting Direction**:
> The request mentions: "make the tasks auto reorder themselves by the descending order of streak counts. The higher the streak the lower the priority."
> In lists, "higher priority" elements are typically placed at the top, and "lower priority" elements at the bottom.
> - **Option A (Recommended)**: Sort in **ascending** order of streak counts (lowest streak at the top, highest streak at the bottom). This aligns with "The higher the streak the lower the priority" so you see tasks you are struggling with at the top, and tasks with high streaks at the bottom.
> - **Option B**: Sort in **descending** order of streak counts (highest streak at the top, lowest streak at the bottom). This aligns with literal "descending order of streak counts" but means higher streaks are at the top (higher priority).
>
> *We will proceed with **Option A** as it satisfies the logical priority description, but we can easily toggle this.*

### Design Decisions
- **Markdown-Safe Sorting**: To preserve your markdown layout, headings, and sections, sorting will happen **within each contiguous checklist chunk** rather than globally.
- **Regular Tasks Placement**: Standard tasks (`- [ ]`) will not be sorted and will retain their relative line positions within their chunk.
- **Cache Storage API**: Since Service Workers cannot access `localStorage` directly, the app will update a shared `/notification-state.json` file in a dedicated `todont-notification-cache` cache whenever tasks are edited. The Service Worker will read this cache to fetch active tasks and manage notification timestamps.

## Proposed Changes

### Task Reordering Logic

#### [MODIFY] [app.js](Documents/GitHub/[personal]/todonts/app.js)
- **Helper Functions**:
  - Add `getStreakOfLine(line)` to parse a markdown line, slugify the task text, and retrieve its streak from state history.
  - Add `sortChunk(chunk)` to extract streak-based task lines, sort them in ascending order of streaks (low streak at top), and place them back in their relative indices.
  - Add `reorderCheckboxChunks(lines)` to scan lines for contiguous checklist chunks (lines containing checkbox list items or `<hr>`) and apply `sortChunk()` to each chunk.
- **Trigger**: Update `handleCheckboxChange()` to run `reorderCheckboxChunks()` right before saving the raw markdown to state.

### Service Worker Background Notifications

#### [MODIFY] [app.js](Documents/GitHub/[personal]/todonts/app.js)
- **State Serialization**:
  - Add `updateServiceWorkerNotificationData()` to compile active (unchecked) tasks and save them along with the last notification timestamps into Cache Storage (`todont-notification-cache`).
  - Update `syncSaveState()` and boot process to trigger `updateServiceWorkerNotificationData()` and ping the service worker to check notifications.
- **Periodic Sync**:
  - Add `registerPeriodicSync(registration)` to register background sync tags for periodic execution when the app is installed.

#### [MODIFY] [sw.js](Documents/GitHub/[personal]/todonts/sw.js)
- **Cache Version**: Update `CACHE_NAME` to `todont-cache-v31`.
- **Notification Manager**:
  - Add `checkBackgroundNotifications()` to read `/notification-state.json` from `todont-notification-cache`.
  - Trigger a random active task notification if $\ge 6$ hours have passed.
  - Trigger a backlog count notification if $\ge 24$ hours have passed.
- **Handlers**: Call `checkBackgroundNotifications()` on `message` (to respond to app events), `fetch` (on resource requests), and `periodicsync` (for background triggers).
