# Implementation Plan - Close Window Confirmation & Responsive Sidebar Exit Button

Add confirmation logic before closing the app/tab when running in PWA standalone mode. Add an explicit "Close App" button in the sidebar drawer for mobile responsive view and resolve bottom padding overlap issues. Additionally, implement the new `<!-- TASKS START HERE -->` scroll target comment.

## User Review Required

> [!IMPORTANT]
> - The browser standard (`beforeunload` event) does not allow custom text like `"Cofirm closing window?"` when closing/reloading the tab directly via browser controls. It will show the browser's default leaving confirmation message.
> - However, for the **back button** (using history state interception) and the **explicit Close App button**, we can and will display the exact `"Cofirm closing window?"` dialog.
> - The "Close App" button will be visible only in PWA standalone mode.
> - A hidden variable `<!-- TASKS START HERE -->` will be automatically injected at the end of the YAML front matter. It will be hidden from the Interactive View but visible in the Markdown Live Editor, allowing the app to calculate the precise scroll offset on mobile and desktop viewports.

### Application Logic

#### [MODIFY] [app.js](Documents/GitHub/%5Bpersonal%5D/todonts/app.js)
- **YAML Loading / Parsing**:
  - Update `loadDataFromMarkdown()` to detect if `<!-- TASKS START HERE -->` is present at the beginning of the markdown body text. If not, insert it (i.e. `body = "<!-- TASKS START HERE -->\n" + body`) to guarantee it is always present right after the closing `---` of the YAML Front Matter.
- **Interactive Markdown Renderer**:
  - Update `compileTextLines()` to ignore the line if it is exactly `<!-- TASKS START HERE -->` so that it is not rendered inside the Interactive View.
- **Close / Back Button Confirmation**:
  - Implement `initCloseConfirmation()` to:
    1. Detect if the app is running in PWA mode (`display-mode: standalone` or `navigator.standalone`).
    2. If running in PWA mode, display the `close-btn` by removing its `hidden` class.
    3. Wire up click listener for `close-btn` to call `confirm("Cofirm closing window?")` and call `window.close()` if accepted.
    4. Intercept back button behavior:
       - Push a state to history: `window.history.pushState({ noBackExitsApp: true }, "")`.
       - Listen to `popstate` event: when popped, prompt with `confirm("Cofirm closing window?")`. If confirmed, call `window.close()`. If cancelled, push the state back to keep interception active.
    5. Add a `beforeunload` listener to show confirmation when the window/app is closed or reloaded directly.
  - Call `initCloseConfirmation()` during the `boot()` phase.
- **Markdown Editor Auto-Scroll**:
  - Modify the click listener for `#toggle-editor-btn`:
    - Find the character position of `<!-- TASKS START HERE -->` in the text area.
    - Calculate the line index of that position by counting newlines before it.
    - Compute the target `scrollTop = linesCount * lineHeight`.
    - Apply this scroll top repeatedly using `requestAnimationFrame` inside a 50ms timeout to ensure the layout engine is finished and the scroll is not overwritten by browser paint reflows.
