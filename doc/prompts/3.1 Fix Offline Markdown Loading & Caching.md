# Fix Offline Markdown Loading & Caching

The markdown documentation files (`guide.md` and `documentation.md`) do not load when the application is offline because:
1. Navigating to `render.html?file=guide.md` passes query parameters, causing the service worker cache matching to fail since `./render.html` is cached without parameters.
2. The various CDN-hosted CSS and JS libraries used by `render.html` (Marked, DOMPurify, KaTeX, Font Awesome, Highlight.js) are not cached by the service worker, rendering the markdown viewer broken when offline.

This plan addresses these issues by:
- Updating `caches.match` in the service worker to use `{ ignoreSearch: true }` so query parameters on `render.html` are ignored.
- Pre-caching all external CDN files and webfonts in `sw.js`'s static assets list.
- Unifying Font Awesome version used in `index.html` to `6.7.2` to match `render.html` and avoid caching redundant versions.
- Adding a dynamic fallback caching strategy in the service worker to cache any other GET requests (like font assets or extra pages) that occur while online.
- Registering the service worker inside `render.js` as well as `app.js` to ensure the PWA features work even if a user bookmarks/enters the viewer page directly.

## User Review Required

> [!IMPORTANT]
> The service worker version will be incremented from `v26` to `v27`. Upon deploying this change, users will need to refresh the page (or let the service worker update in the background) to cache the new CDN assets.

## Proposed Changes

---

### Caching and Service Worker

#### [MODIFY] [sw.js](Documents/GitHub/[personal]/todonts/sw.js)
- Add external CDN CSS, JS, and Font files to the `ASSETS` cache list.
- Update `caches.match` in the `fetch` listener to include `{ ignoreSearch: true }`.
- Update the `fetch` handler to dynamically cache successful GET requests (like dynamically loaded webfonts or extra markdown files) that aren't pre-cached.
- Increment `CACHE_NAME` version to `todont-cache-v27` to invalidate old cache and force fetching new assets.

#### [MODIFY] [render.js](Documents/GitHub/[personal]/todonts/render.js)
- Register the service worker on page load (just like in `app.js`) so the app is robust if entering via `render.html`.

---

### Unified Asset Linking

#### [MODIFY] [index.html](Documents/GitHub/[personal]/todonts/index.html)
- Update Font Awesome CDN version link to `6.7.2` to align with the cached version.

## Verification Plan

### Automated Tests
- Since this is a client-side only PWA, we don't have automated test commands. Verification will be done manually.

### Manual Verification
1. Open the application.
2. Check Chrome DevTools -> Application -> Service Workers to verify the service worker is registered and active.
3. Open DevTools -> Application -> Cache Storage to verify the cache `todont-cache-v27` is populated with the CSS, JS, markdown, and font assets.
4. Set Chrome DevTools to "Offline" mode (Network tab).
5. Click on the "User Guide" or "Documentation" footer links.
6. Verify `render.html` loads, displays the back buttons, the icons, and renders the markdown contents of `guide.md` / `documentation.md` completely offline.
