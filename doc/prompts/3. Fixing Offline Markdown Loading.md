### Why is it failing offline?
1. **Query parameters mismatch**: When clicking "User Guide" or "Documentation", you go to `render.html?file=guide.md` or `render.html?file=documentation.md`. The service worker's cache lookup (`caches.match`) checks the exact URL by default, which fails to find `render.html` because of the query parameters.
2. **Missing CDN dependencies offline**: The rendering engine in `render.html` depends on multiple third-party libraries (Marked, DOMPurify, KaTeX, Font Awesome, and Highlight.js) loaded via CDNs. These are not cached, so the viewer breaks offline even if the HTML itself loads.

### Summary of Changes

1. **Service Worker (`sw.js`) Updates**:
   - **Pre-cached CDN Resources**: Added all critical third-party CSS, JS, and Webfont dependencies (Marked, DOMPurify, KaTeX, Highlight.js, and Font Awesome) to the static `ASSETS` cache list.
   - **Query String Support**: Enabled `{ ignoreSearch: true }` in `caches.match` inside the `fetch` listener. This ensures that navigations to `render.html?file=guide.md` (which contain query parameters) match the cached `./render.html` entry.
   - **Dynamic Runtime Caching**: Added a dynamic cache fallback to the fetch event handler, ensuring any runtime `GET` requests (such as math fonts or other documentation files loaded online) are automatically saved to the cache.
   - **Cache Version Bumped**: Incremented `CACHE_NAME` to `todont-cache-v27` to trigger a clean update on the client.

2. **Standalone SW Registration (`render.js`)**:
   - Added service worker registration to the initial load of `render.js` so offline capabilities remain robust if the user bookmarks or lands directly on `render.html`.

3. **Unified Assets (`index.html`)**:
   - Unified the Font Awesome CDN version link to `6.7.2` (matching `render.html`) to prevent redundant assets from being cached.
